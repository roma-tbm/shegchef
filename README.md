# Конструктор кухни

Скрипт, который по заданному меню считает продукты, задачи для смены и время
каждой операции, а затем собирает готовую книгу Excel для печати.

Расчёт полностью на Python — в книге нет формул, которые «сломаются»,
если её открыть в другой программе.

## Быстрый старт

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python build.py
```

Книга `Кухня_конструктор.xlsx` соберётся и откроется сама.

## Как пользоваться

1. Запустите `build.py` — получите книгу с демо-меню.
2. Откройте лист **«Конструктор меню»** и впишите блюдо, порции и время выдачи.
3. Запустите `build.py` ещё раз — всё пересчитается по вашему меню.

Файл запоминает ваше меню: при повторном запуске берутся строки из книги,
а не демо-данные. Флаг `--fresh` возвращает демо-меню.

### Ключи запуска

| Ключ | Что делает |
|---|---|
| `--out ПУТЬ` | сохранить книгу под другим именем |
| `--day ДД.ММ.ГГГГ` | дата смены, по умолчанию сегодня |
| `--menu N` | порции для всех блюд демо-меню |
| `--fresh` | забыть правки и взять демо-меню |
| `--no-open` | не открывать файл после сборки |

## Что внутри книги

| Лист | Для кого |
|---|---|
| **Лист смены** | печать: меню, блоки задач по ролям, продукты, контроль, примечания |
| **Меню** | что готовим и к какому времени |
| **Продукты** | что купить, сколько есть и хватает ли |
| **Карта задач** | какая операция для какого блюда, продукты, длительность |
| **Тайминг** | кто, что и когда делает по часам |
| **ТТК** | технологические карты |
| **Ингредиенты** | нормы на порцию по всем блюдам |
| **Конструктор меню** | лист для ручных правок |
| **Задачи** | полный список операций с ролями и цехами |
| **Списания** | что списать по остаткам |
| **Инвентаризация** | остатки и минимальные запасы |
| **Инструкция** | как читать книгу |

## Как считается

**Продукты.** Норма на порцию из ТТК × порции. Один и тот же продукт в трёх
блюдах — одна строка, а не три: в ней видно, сколько нужно на каждое блюдо.
Поштучные продукты (ломтик хлеба, ветчина) не переводятся в килограммы.

**Задачи.** Типовая операция, нужная нескольким блюдам, схлопывается в одну
задачу. Например, «Подготовка лука репчатого» — одна строка на солянку, пюре
и салат, а не три. Приём пищи — одна задача на весь приём, даже если блюд пять.

**Время.** Обратный отсчёт от времени выдачи. Каждое блюдо стартует так, чтобы
закончиться к своему сроду; общая заготовка овощей идёт перед самым ранним
стартом горячего цеха. Каждая роль получает список дел без наложений, где
возможно, а пиковая нагрузка попадает в предупреждения.

**Предупреждения** печатаются в консоль и в блок «Важно» на листе смены:
не хватает продуктов по остаткам, две роли-«уши» нуждаются в пересечении
по времени, блюдо не влезает до выдачи.

## Допущения демо-меню

Демо взято из `input1.md` (5 блюд по 50 порций, завтрак к 08:00, обед к 12:00):

- 5 л молока на кашу и пюре разделены как 40 мл + 60 мл на порцию;
- 3 банки горошка приняты как 3 × 400 г нетто = 24 г на порцию;
- хлеб, ветчина и сыр — по 1 ломтику на порцию, без пересчёта в килограммы;
- остатки в листе «Продукты» демонстрационные — замените на фактические.

Все эти допущения печатаются в блоке «Примечания и предположения» на листе
смены, чтобы их не пришлось держать в голове.

## Тесты

```bash
.venv/bin/python -m pytest tests/ -q
```

`tests/test_input1_baseline.py` — эталонные цифры из `input1.md` на 50 порций.
`tests/test_excel.py` — сборка книги и главный пользовательский сценарий:
правка меню → пересчёт продуктов и задач.

## Структура

```
kitchen/
  models.py      доменные объекты: блюда, продукты, задачи, смена
  seed.py        демо-данные из input1.md
  core/
    ingredients.py   расчёт продуктов и группировка по обработке
    tasks.py         генерация и объединение задач
    timing.py        обратный тайминг и нагрузка по ролям
    shiftsheet.py    сборка итогового объекта смены
  excel/
    builder.py   листы и форматирование
    menu_io.py   чтение меню из книги
build.py         CLI
```

Ядро не знает про Excel: `calculate_ingredients`, `generate_tasks`,
`calculate_backward_timing` и `build_shift_sheet` работают с обычными
объектами. Это позволяет менять формат книги, не трогая расчёт.
