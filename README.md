# ShegChef — конструктор кухни

Локальный планировщик кухонной смены на Python 3.10+: считает продукты,
задачи и время операций, собирает книгу Excel для печати. Есть CLI
и веб-интерфейс Streamlit.

Продукты, задачи и тайминг рассчитываются в Python и записываются в книгу
готовыми значениями. Счётчики поиска в «Конструкторе меню» используют
формулы Excel `COUNTIF`/`COUNTIFS`; их отображение зависит от программы,
в которой открыта книга.

## Быстрый старт

Запускайте команды из корня проекта.

macOS / Linux (Python 3.10+):

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python build.py --fresh
```

Windows 10 (Python 3.10+ должен быть в PATH):

```bat
py -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python build.py --fresh
```

Команда с `--fresh` создаёт книгу `Кухня_конструктор.xlsx` с демо-меню
и открывает её. Для меню выбранной даты запускайте без `--fresh`, как описано ниже.

Папку `.venv` переносить между компьютерами нельзя — она собрана под
конкретную ОС и версию Python. На новом компьютере создайте её заново
командами выше; переносить нужно только исходники и `requirements.txt`.

## Как пользоваться

1. Создайте книгу с демо-меню: `.venv/bin/python build.py --fresh`.
2. На листе **«Конструктор меню»** выберите блюда в окнах приёмов пищи,
   укажите порции и время выдачи. Для подбора по запросу используйте
   `--search`, как описано ниже: обычный запуск сам блюда не подбирает.
3. Сохраните и закройте книгу, затем запустите
   `.venv/bin/python build.py --from-book`. Для другого имени книги добавьте
   `--out ПУТЬ`. В Windows используйте `.venv\Scripts\python`.

Обычный запуск без ключей меню **не** берёт из книги. Сначала читается
сохранённая запись выбранной даты в общем каталоге данных `~/.shegchef`
(или каталога, заданного `--data-dir`/`SHEGCHEF_DATA_DIR`): запись, даже
сознательно пустая, важнее автоматической заготовки. Без записи будний день
получает заготовку недельного плана `kitchen/menu_week.py`, выходной — пустое
меню. `--fresh` игнорирует и сохранённую запись: берётся демо-меню.

Чтобы прочитать меню, написанное руками в книге `--out`, нужен явный
ключ `--from-book` (или `--week`, который читает «План меню»). Это изменение
стандартного CLI-сценария: раньше книга выбирала меню неявно. Теперь CLI и
Streamlit читают один и тот же набор данных, поэтому смена выходного пути
книги (`--out`) не меняет меню, настройки, статусы, комментарии и отклонения.

### Какие правки сохраняются

Из Excel читаются «Конструктор меню» (при явном `--from-book` или `--search`)
и, при `--week`, «План меню». Каталог блюд, нормы ингредиентов, длительности
операций, остатки и минимальные запасы задаются в `kitchen/seed.py`
и `kitchen/menu_week.py`. Чтобы изменить их для расчёта, нужно обновить
соответствующие Python-данные.

Правки листов «Ингредиенты», «Продукты», «Задачи», «Списания»
и «Инвентаризация» не импортируются и будут перезаписаны при пересборке.
Ручные журналы сохраняйте в отдельной копии книги.

### Ключи запуска

| Ключ | Что делает |
|---|---|
| `--out ПУТЬ` | куда сохранить книгу; сама меню не выбирает |
| `--day ДД.ММ.ГГГГ` | дата смены, по умолчанию сегодня |
| `--menu N` | порции для всех блюд демо-меню |
| `--week ДЕНЬ` | взять готовый день из листа «План меню»: `пн`, `Понедельник` или `1` |
| `--search ЗАПРОС` | подобрать блюда из ТТК и поставить их в свободные строки окон |
| `--scale КОЭФ` | умножить порции меню до расчёта (например `1.3` для смены на 65) |
| `--fresh` | игнорировать сохранённую запись: взять демо-меню, а с `--week` — план из кода |
| `--from-book` | явный Excel-источник: взять меню из книги `--out` |
| `--data-dir ПУТЬ` | общий каталог данных (по умолчанию `~/.shegchef` или `SHEGCHEF_DATA_DIR`) |
| `--menu-file ПУТЬ` | явный файл меню-хранилища вместо `menu.json` и `меню.json` |
| `--settings ПУТЬ` | файл настроек смены (по умолчанию `settings.json` в каталоге данных) |
| `--notes ПУТЬ` | файл комментариев и отклонений (по умолчанию `notes.json`) |
| `--statuses ПУТЬ` | файл статусов работ (по умолчанию `statuses.json`) |
| `--reports ПУТЬ` | файл субботних отчётов (по умолчанию `reports.json`) |
| `--print-dir ПУТЬ` | папка печатных форм (по умолчанию «Печатные формы» рядом с книгой) |
| `--no-print` | не выгружать печатные формы |
| `--no-open` | не открывать файл после сборки |

`--menu` применяется к демо-меню. С `--week` или `--search` этот флаг
игнорируется. Чтобы получить демо на 60 порций, используйте `--fresh --menu 60`.
Книга как источник меню выбирается только явно: ключом `--from-book` (текущая
дата) или `--week` (день недели из «Плана меню»). Старый сценарий правки Excel
сохраняется именно через `--from-book`.

### Общий каталог данных

CLI и Streamlit читают одни и те же файлы в одном каталоге (по умолчанию
`~/.shegchef`): `menu.json`, `settings.json`, `notes.json`, `statuses.json`,
`reports.json`. Обычный запуск Streamlit использует ту же конфигурацию:
каталог задаётся переменной `SHEGCHEF_DATA_DIR`, а явный файл меню —
переменной `SHEGCHEF_MENU_FILE`. У CLI это `--data-dir`, `--menu-file`,
`--settings`, `--notes`, `--statuses`, `--reports`; явные пути имеют приоритет
над каталогом.

Повреждённый или структурно неверный JSON любого из этих файлов — понятная
ошибка при чтении и сохранении; исходные байты не изменяются. Отсутствие файла
остаётся допустимым отдельным состоянием. Существующий файл с `null` или другим
скаляром (`false`, число, строка, список) — тоже ошибка, а не «пусто»: иначе
следующее сохранение молча заменило бы чужой файл. Это одинаково действует
в CLI и в вебе.

Старые файлы рядом с книгой (`меню.json`, `settings.json`, `notes.json`)
продолжают работать: укажите их явными путями. Автоматической миграции нет —
ничего не перезаписывается. Оба имени меню (`menu.json` и `меню.json`)
поддерживаются вместе: непересекающиеся даты читаются совместно, а разные
записи одной даты (включая конфликт пустой и непустой) дают понятную ошибку
**до** записи. Выбрать один источник в этом случае можно ключом `--menu-file`
(у веба — переменной `SHEGCHEF_MENU_FILE`). Повреждённый JSON — тоже понятная
ошибка: испорченный файл не перезаписывается пустыми данными.

### Печать маршрутов и общего плана

CLI выгружает печатные формы в папку «Печатные формы» рядом с книгой
(ключи `--print-dir ПУТЬ` и `--no-print`). Общий план, маршрут каждого
сотрудника и субботний отчёт — обычный TXT. Формы рассчитаны на A4 в альбомной
ориентации, моноширинный шрифт 10 pt и поля 28 pt: ширина строки не превышает
130 символов (≈783 pt из доступных ≈786 pt). Длинные ячейки переносятся по
словам, поэтому исполнитель, статус и комментарий остаются на странице, а
уменьшать шрифт вручную не нужно. Открывая TXT во вьюере, задайте эти же
параметры страницы и шрифта.

### Поиск блюд в ТТК

**«Конструктор меню»** разбит на окна: сверху окно поиска, ниже — отдельное
окно позиций на каждый приём пищи, который есть в ТТК. В окне «Обед»
выпадающий список содержит только обеденные блюда.

Поиск ищет часть названия без учёта регистра. В ячейку «Запрос» впишите,
например, `суп` (найдёт «Гороховый суп с копчёностями»,
но не все блюда категории «Супы»).
Счётчики покажут, сколько блюд найдено всего и в каждой папке ТТК. Дальше два пути:

* **руками** — выбрать блюдо из списка в своём окне;
* **командой** — поставить найденное само:

```bash
.venv/bin/python build.py --search суп      # сразу с запросом
.venv/bin/python build.py --search          # взять запрос из ячейки книги
```

Перед `--search` без значения сохраните запрос в книге.
Команда занимает только свободные строки, берёт порции из своего окна
(если их нет — из других окон, иначе 50) и не
записывает блюдо, которое уже стоит в этом окне, — её можно запускать
повторно. Не хватило строк — скажет об этом. С `--week` ключ не сочетается:
сначала берите день из плана либо ищите блюда.

### Меню на неделю

В книге есть лист **«План меню»** — 27 позиций на Пн–Пт. День недели
разворачивается в обычную смену, дальше всё считается как обычно:

```bash
.venv/bin/python build.py --week пн
.venv/bin/python build.py --week Среда
.venv/bin/python build.py --week 3 --day 30.09.2026
```

Если шеф правил «План меню» руками, ключ возьмёт план из книги; иначе —
заготовку из `kitchen/menu_week.py`. Правка порций в плане не теряется:
собирая смену, скрипт записывает в книгу тот план, по которому её собрал.
Флаг `--fresh` всегда берёт заготовку из кода.

После `--week` день недели остаётся в листе «Конструктор меню», поэтому
следующий обычный запуск продолжит именно его. Чтобы вернуть демо-меню,
нужен `--fresh`.

Нормы 24 новых блюд — типовые, на порцию. Это заготовка под ваш продукт,
а не рецепт шефа: изменяйте нормы в `kitchen/menu_week.py`
и пересобирайте книгу. Правка листа «Ингредиенты» в расчёт не попадёт.

### Масштабирование порций

`--scale` меняет порции **до** расчёта смены, поэтому потребность в продуктах
пересчитывается по новым количествам. Задачи и тайминг строятся заново,
но длительности операций остаются заданными в шаблонах: рост порций
сам по себе не увеличивает время готовки.

```bash
.venv/bin/python build.py --scale 1.3    # 50 порций → 65
.venv/bin/python build.py --week чт --scale 1.5
```

Масштабированные порции записываются обратно в книгу. Повторный `--scale`
умножит уже сохранённые количества: 50 → 65 → 85 при коэффициенте 1.3.
Для повторяемого расчёта от демо используйте `--fresh --scale 1.3`.

Округление математическое: 3 × 1.3 = 3.9 → 4, 7 × 0.5 = 3.5 → 4. Блюдо не
может получить меньше 1 порции. Коэффициент обязан быть больше нуля:
`--scale 0`, отрицательное число или не-число — ошибка, книга не соберётся.

## Веб-интерфейс

Помимо CLI есть локальное веб-приложение на Streamlit — тот же расчёт, но с
редактированием меню глазами:

```bash
.venv/bin/python -m streamlit run app.py
```

В Windows команда запуска: `.venv\Scripts\python -m streamlit run app.py`.
По умолчанию приложение доступно по адресу `http://localhost:8501`. Вкладки:

| Вкладка | Что делает |
|---|---|
| **Меню** | добавить блюдо из каталога ТТК (с фильтром и поиском), править порции/время, отметить «Убрать», предпросмотр масштабирования |
| **Расчёт смены** | посчитать смену текущего дня и посмотреть предупреждения |
| **Продукты и дефицит** | что купить, остатки и чего не хватает |
| **Задачи по ролям** | хронологический список задач по каждой роли |
| **Маршруты** | общий план и маршрут каждого сотрудника; отметки выполнения, статус отдельно от нарушений |
| **Экспорт** | собрать книгу Excel и скачать задания текстом (файл целиком или по ролям) |
| **Настройки смены** | длительности и окна обязанностей, численность и графики, персональные строки, исполнитель бракеража |
| **Отклонения** | комментарий и причина отклонения по каждой работе: задержка, замена продукта, порции, оборудование, другое |
| **Отчёт за субботу** | расход сырья, выход полуфабрикатов и маркировка по субботам |

Слева — рабочая дата и выбор дня из недельного плана. Правки меню хранятся
по датам в общем каталоге данных (`~/.shegchef`), отдельно от Excel. Обычный
запуск читает тот же каталог данных, что и CLI: `SHEGCHEF_DATA_DIR`
(или `~/.shegchef`), оба имени меню (`menu.json` и `меню.json`), а конфликт
одной даты показывает понятной ошибкой вместо записи.

Правка дня сохраняется **в тот же источник, откуда она прочитана**: в файл,
заданный `SHEGCHEF_MENU_FILE` (если он выбран явно), либо в то имя меню
(`menu.json` или `меню.json`), где уже есть запись этой даты. Так правка даты
из `меню.json` не создаёт вторую запись в `menu.json` и не рождает конфликт
двух имён. Новые даты без записи попадают в `menu.json`. При запуске и переключении даты загружается
сохранённое меню этого дня, включая сознательно очищенное. Если записи нет,
будний день получает заготовку из `kitchen/menu_week.py`, выходной — пустое
меню. Меню следующего дня берётся только из сохранённой записи: без неё
подготовка остаётся неготовой, а не подтягивает план книги.

Выбор дня из плана заменяет текущее меню заготовкой выбранного буднего дня
для установленной рабочей даты; саму дату не меняет. Заготовка сохраняется
в JSON после редактирования меню. Переключение даты сбрасывает прежний
расчёт, предпросмотр масштабирования и подготовленный экспорт.

### Настройки, отклонения и отчёт субботы

Три вкладки пишут и читают те же файлы, что и CLI: `settings.json`,
`notes.json` и `statuses.json` в общем каталоге данных (`~/.shegchef`).
Флаги `--settings`, `--notes` и `--statuses` у `build.py` читают их же,
поэтому печать из терминала и расчёт в браузере не расходятся. CLI передаёт
сохранённые статусы в расчёт так же, как интерфейс: отметка «сделано»
не теряется при экспорте из терминала.

- Длительности и окна — по каждой обязанности каталога. Пустое поле означает
  «в источнике не задано»: работа попадает в план с видимой причиной, а не с
  выдуманным временем. Проверка ввода отвергает мусор (`не число`) с понятной
  ошибкой и ничего не записывает.
- Общие настройки и настройки отдельных дней живут в одном файле: день можно
  настроить отдельно, не дублируя общее, и сохранение общих настроек не
  стирает дневные.
- Отклонение требует пояснения, а задержка — ещё и минут. Форма сохраняется
  целиком: снятая строка исчезает, а не остаётся призраком в следующей печати.
- Комментарий и отклонение печатаются в одной ячейке со своей работой, вместе
  с вычисленным статусом: отметка человека «сделано» не скрывает нарушение.
- Субботний отчёт не списывает складские остатки. Расход сырья и выход
  полуфабриката — разные величины в разных единицах; выход остаётся пустым,
  пока норма выхода не подтверждена источником.

### Ранее сохранённые отметки выдачи

До разделения выдачи на роли у завтрака и обеда был один общий ID
(`П-breakfast-serving`, `П-lunch-serving`). Теперь у выдачи отдельные работы
на шефа, повара и разнорабочего. Если в `statuses.json` или `notes.json`
остался старый ID, его статус, комментарий и отклонение не теряются и не
раздаются новой бригаде: прежний исполнитель в хранилище не сохранён, поэтому
запись показывается отдельным историческим фактом — во вкладке «Маршруты»,
строкой во вкладке «Отклонения» и примечанием в общем плане. Она не меняет
расчётные статусы участников и не влияет на готовность смены. Сохранение формы
дня оставляет старую запись на месте; новые отметки ставятся как обычно.

Telegram никуда не отправляется: «Задачи по ролям» готовы как обычный текст,
который можно вставить в любой мессенджер вручную. Авторизации, облака и базы
данных в веб-версии нет — это локальный планировщик.

## Что внутри книги

| Лист | Для кого |
|---|---|
| **Лист смены** | печать: меню, блоки задач по ролям, продукты, контроль, примечания |
| **Меню** | что готовим и к какому времени |
| **Продукты** | что купить, сколько есть и хватает ли |

### Ссылка на состав

Блюдо — ссылка, а не текст. Нажали на название в **«Меню»**, **«ТТК»**,
**«Конструкторе меню»** или **«Плане меню»** — открылся блок этого блюда
на листе «Ингредиенты». Оттуда ссылка «к ТТК» возвращает на карточку.
На «Ингредиентах» название блюда пишется один раз на весь блок, а не
повторяется в каждой строке.

Скрытый лист «Справочник блюд» нужен потому, что Excel не принимает список
длиннее 255 символов в одной формуле проверки ввода, а блюд в каталоге 29.
Блюда одного приёма пищи в нём идут подряд — так каждое окно получает свой
список, а не весь каталог сразу.

### Папки в ТТК

ТТК разложен по двум уровням: сначала приём пищи, внутри — подгруппа
(«Супы», «Горячее», «Каши»…). На полосе папки написано, сколько в ней блюд.
Папки сворачиваются кнопкой «−» в левом поле, поэтому на экране остаются
только названия папок, а состав открывается по конкретному блюду.

## Как считается

**Продукты.** Норма на порцию из ТТК × порции. Один и тот же продукт в трёх
блюдах — одна строка, а не три: в ней видно, сколько нужно на каждое блюдо.
Поштучные продукты (ломтик хлеба, ветчина) не переводятся в килограммы.
Дефицит = максимум из нуля и «потребность + минимальный запас − остаток».

**Задачи.** Типовая операция, нужная нескольким блюдам, схлопывается в одну
задачу. Например, «Подготовка лука репчатого» — одна строка на солянку, пюре
и салат, а не три. Каждая общая операция контроля или расстановки
создаётся один раз на приём пищи, даже если блюд пять.

**Время.** Обратный отсчёт от самой ранней выдачи внутри каждого приёма пищи.
Заготовки планируются перед стартом блюд, которым они нужны; готовка ждёт
завершения своих заготовок. Начало цепочек готовки ограничено 06:00.
Пересечения задач одной роли возможны: пиковая нагрузка показывается
в предупреждениях, а блюдо, не успевающее к выдаче, отмечается отдельно.

**Предупреждения** печатаются в консоль и в блок «Важно» на листе смены:
не хватает продуктов с учётом минимального запаса, одной роли требуется
несколько сотрудников одновременно, блюдо не успевает к выдаче.

## Допущения демо-меню

Демо-меню содержит 5 блюд по 50 порций, завтрак к 08:00, обед к 12:00:

- 5 л молока на кашу и пюре разделены как 40 мл + 60 мл на порцию;
- 3 банки горошка приняты как 3 × 400 г нетто = 24 г на порцию;
- хлеб, ветчина и сыр — по 1 ломтику на порцию, без пересчёта в килограммы;
- остатки демонстрационные — для расчёта замените их в исходных
  Python-данных; правки листа «Продукты» при пересборке не читаются.

Все эти допущения печатаются в блоке «Примечания и предположения» на листе
смены, чтобы их не пришлось держать в голове.

## Структура

```
kitchen/
  models.py      доменные объекты: блюда, продукты, задачи, смена
  seed.py        демо-данные и полный каталог
  menu_week.py   меню Пн–Пт: 24 карточки, продукты, операции
  web/
    scaling.py     чистое масштабирование порций (без Streamlit/Excel)
    messages.py    текстовые задания по ролям из посчитанной смены
    dataset.py     единый каталог данных и чтение menu.json/меню.json
    menu_store.py  локальное JSON-хранение меню по датам
    status_store.py  статусы работ по датам
    catalog.py     глобальный поиск по ТТК и добавление блюда (приём из карточки)
  core/
    ingredients.py   расчёт продуктов и группировка по обработке
    tasks.py         генерация и объединение задач
    timing.py        обратный тайминг и нагрузка по ролям
    shiftsheet.py    сборка итогового объекта смены
  excel/
    builder.py   листы и форматирование
    folders.py   разбор каталога по папкам: приём пищи → подгруппа
    menu_io.py   чтение меню и недельного плана из книги
    picker.py    подбор блюд по запросу из окна поиска
    styles.py    шрифты, заливки, рамки, полосы и сворачивание
app.py             веб-интерфейс Streamlit
build.py         CLI
```

Ядро не знает про Excel: `calculate_ingredients`, `generate_tasks`,
`calculate_backward_timing` и `build_shift_sheet` работают с обычными
объектами. Это позволяет менять формат книги, не трогая расчёт.
Пакет `kitchen/web` тоже чистый — Streamlit живёт только в `app.py`, поэтому
всю веб-логику можно тестировать без запуска браузера.
